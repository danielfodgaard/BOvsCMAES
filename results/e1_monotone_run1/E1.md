# E1: monotone transforms of f

**What.** Run CMA-ES and BO on g(f) for strictly increasing g, and compare with the run on f under the same seed.
CMA-ES only uses the ranking of the f-values, so in theory it cannot tell g(f) from f. BO fits a GP to the
values, so it can.

**Setup.**
- Problem: H1's 5-D ellipsoid (condition number 100, x* in [−2, 2]⁵, box [−5, 5]⁵), seeds 0–9. The seed fixes x*,
  the CMA-ES start point and the Sobol initial design, so all three are the same for every g.
- g: f^p for p ∈ {1/4, 1/2, 1, 2, 4}; the saturating f/(f + 100), where c = 100 is about the 1 % quantile of f over the box;
  and the control 1000·f. The control is affine, so by H1 it should have no effect: its gap is how far
  BO's result moves from rounding alone.
- CMA-ES: H1's runner (pycma 4.5.0, σ₀ = 2.5, popsize 8). *Fixed budget*: 2000 evaluations, f-based
  termination off. *Default stopping*: pycma's termination, capped at 2000 evaluations.
- BO: H1's runner (BoTorch 0.18.1, `SingleTaskGP` defaults: ARD RBF kernel, `Standardize`, `Normalize` on the inputs),
  LogEI, 10 Sobol points + 90 iterations. *Default*: the GP is fitted to g(f). *Ranks*: the GP is fitted to the ranks of
  g(f), recomputed every iteration (Shirakawa's fix).
- Score: best **untransformed** f. Gap = log10 best f on g − log10 best f on f, same seed and arm; > 0 means worse on g.

**Result.** Median gap over 10 seeds (log10). In brackets: evaluations used by CMA-ES with default stopping.

| g | CMA-ES, fixed budget | CMA-ES, default stopping | BO, default | BO, ranks |
| --- | --- | --- | --- | --- |
| f (reference) | 0 | 0 (1288) | 0 | 0 |
| f^0.25 | 0 | −7.7 (1880) | +2.1 | 0 |
| f^0.5 | 0 | −7.7 (1880) | +1.3 | 0 |
| f^2 | 0 | +5.3 (864) | +2.4 | 0 |
| f^4 | 0 | +8.7 (684) | +3.1 | 0 |
| f/(f+100) | 0 | +2.1 (1156) | +1.3 | 0 |
| 1000·f (control) | 0 | −2.6 (1516) | −0.1 | 0 |

Every 0 in the table is exact: the runs are bit-identical. Median best f after 100 evaluations on f: BO default 0.08,
BO ranks 5.9, CMA-ES 25.

**Found.**
1. **CMA-ES's search is invariant; only its stopping rule is not.** With a fixed budget, the mean and σ of all 250
   generations are bit-identical for all seven g. Default stopping (`tolfun`, `tolfunhist`) compares *absolute*
   differences in g, so the run stops once the spread in f near the optimum drops below about 10⁻¹¹ / g′(f). This
   predicts the gap: −log10 1000 = −3 for 1000·f (observed −2.6) and +log10 100 = +2 for f/(f+100) (observed +2.1).
   f² and f⁴ stop 400–600 evaluations early, at f ≈ 10⁻⁹ and 10⁻⁶ instead of 5·10⁻¹⁵. For p < 1, `tolfun` cannot
   fire before floating-point resolution, so the x-based `tolx` stops both runs at the same point, later and better
   (f ≈ 10⁻²²).
2. **Default BO is not invariant, and f itself is its best representation here.** Every nonlinear g made BO worse,
   in all 60 (g, seed) pairs, by +0.42 to +3.5. The control's gaps lie in [−0.35, +0.20], so the effect comes from the
   nonlinearity, not from rounding; this is the separation H1 was meant to make possible. The transform even decides which method wins at 100
   evaluations: on f, BO beats CMA-ES by about 2.5 orders of magnitude, on f² they tie, and on f⁴ BO loses (88 vs 25).
3. **Ranks make BO exactly invariant, at a cost.** Proposals are bit-identical across all seven g, but on f itself
   rank-BO ends about 2 orders of magnitude worse than default BO (paired median +2.0, worse in 10/10 seeds). It stops
   improving at evaluation 27 (median), against 65 for default BO. Rank-BO beats default BO only where the transform hurts most
   (f^0.25, f², f⁴), and still beats CMA-ES at this budget.
4. **GP fit (a pointer, not yet an explanation).** Under f² and f⁴, the default GP's lengthscales for dimensions 1–2
   grow to 40–70 (normalised units), so it effectively ignores those coordinates. Under f^0.25 and f/(f+100), the
   fitted noise rises from BoTorch's floor of 10⁻⁴ to about 10⁻². The rank GP's noise sits at about 2·10⁻². However, the
   remaining error at BO's best point under f⁴ is spread over all five dimensions, so the lengthscales alone do not
   explain the f⁴ gap.

**A prediction that failed.** Mid-run, default BO on f looked limited by the noise floor: improvements near the
optimum are tiny compared with the spread of f. So compressing transforms (p < 1, saturating) looked likely to
help. They hurt instead. f^p with p < 1 has a cusp at the optimum, which a smooth RBF GP models as noise.

**Choices to review.**
- Budgets: BO 100 evaluations; CMA-ES 2000 (H1's value).
- One saturating constant (c = 100); a second value, e.g. c = median f ≈ 1200, would give a mild case.
- Rank variant: plain ranks. Normal scores Φ⁻¹((r − ½)/n) are equally invariant and separate the best points
  more, which may reduce the cost in finding 3.
- LogEI only; H1 also ran EI.
- Inherited from H1: the CMA-ES start point is exactly x₀ = 2.5·x*, because both are drawn from the same seeded
  stream. Harmless for the paired gaps, but it matters for any absolute CMA-ES result. Fixing it changes H1 too.
  Also σ₀ = 2.5, whereas the outline says 3.
